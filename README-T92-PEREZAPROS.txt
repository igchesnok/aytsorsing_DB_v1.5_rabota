ЗАДАЧА T92
----------
Доработка проверки ссылки (кнопка «🔗 Проверить загрузку», страница «Запросы
на коммерческие предложения»): после T91 (таймаут 30 с) нестабильные ошибки
«Таймаут 30 с — сервер не ответил» сохранились — при СЛЕДУЮЩЕМ перезапросе тот
же файл скачивается. Предложено пользователем: на ошибки типа «сервер не
 ответил» добавить перезапрос файла, а таймаут вернуть к 15 секундам.

ПРИЧИНА
-------
Сервер Яндекс.Диска периодически подзависает: одна попытка может не уложиться
в любой разумный таймаут, но повторный запрос того же файла проходит. Увеличе-
ние таймаута (T91) проблему не сняло — честные, но «подзависшие» файлы всё ещё
помечались «НЕ грузятся». Отдельные файлы стабильно дают «соединение оборвано
до начала передачи файла» — Яндекс обрывает передачу; перезапрос такой файл
пробует ещё раз, но если обрыв повторяется — это битый файл (лечится перезак-
ладкой, кнопка «📧 Сообщить технологу»).

ЧТО СДЕЛАНО
-----------
src/routes/zaprosKpRoutes.js (guard «✅ T92»):
1) CHECK_URL_FILE_TIMEOUT_MS 30000 -> 15000 — возврат к 15 с на попытку;
2) CHECK_URL_FIRST_BYTE_MS 20000 -> 12000 — возврат ожидания первого байта;
3) новые константы: CHECK_URL_RETRIES = 1 (итого ДО 2 ПОПЫТОК на файл) и
   CHECK_URL_TRANSIENT_RE — классификатор транзиентных ошибок: «сервер не
   ответил», «Таймаут соединения», «не начал передачу файла», «соединение
   оборвано», «ошибка сети», «закрыл соединение, не передав файл», «ошибка
   при передаче файла»;
4) worker проверки: при транзиентной ошибке файл ПЕРЕЗАПРАШИВАЕТСЯ — заново
   получают свежую ссылку скачивания через API Яндекса и пробно скачивают;
   общий бюджет проверки (120 с) соблюдается; в отчёт добавляется признак
   retried. РЕАЛЬНЫЕ ошибки файла (HTTP 4xx/5xx, HTML вместо файла, битые
   редиректы) НЕ перезапрашиваются — как и раньше.
public/js/modules/requests.js:
5) в полном списке файлов у вытянутых со 2-й попытки — жёлтая пометка
   «↻ со 2-й попытки» (видно, что автоперезапрос сработал).

КАК ПОЛЬЗОВАТЬСЯ
----------------
Без изменений: поле «Ссылка» -> кнопка «🔗 Проверить загрузку». Каждый файл
пробно скачивается (до 2 попыток по 15 с). Если файл вытянут со второй
попытки — он считается доступным, в отчёте помечен «↻ со 2-й попытки».
Если обе попытки дали транзиентный сбой — файл показан как «НЕ грузится» с
причиной (например, «соединение оборвано до начала передачи файла»). Для
стабильно битых файлов (HTTP 500 / постоянный обрыв) — кнопка «📧 Сообщить
технологу»: письмо с перечнем непрогрузившихся файлов и просьбой перезаложить
их или предоставить новую ссылку.
