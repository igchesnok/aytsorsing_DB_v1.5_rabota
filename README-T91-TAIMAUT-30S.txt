ЗАДАЧА T91
----------
Увеличить таймаут проверки ссылки на документацию (страница «Запросы на
коммерческие предложения», кнопка «🔗 Проверить загрузку»): 15 секунд мало —
при нескольких прогонах одной и той же ссылки ошибка «Таймаут 15 с — сервер
не ответил» выскакивает на разных файлах, т.е. сервер Яндекса периодически
подзависает. Предложено и принято: увеличить таймаут до 30 секунд.

ПРИЧИНА
-------
Пробное скачивание каждого файла (Range-GET) и запросы к API Яндекс.Диска
ждали ответа всего 15 с (CHECK_URL_FILE_TIMEOUT_MS = 15000). При загрузе
Яндекса честные, но медленные файлы помечались как «НЕ грузятся» — причём на
каждом прогоне разные, что вводит в заблуждение.
Стабильная ошибка «HTTP 500 — file IO failure: no successful lookup result»
на отдельных файлах — это НЕ таймаут: Яндекс сам отвечает ошибкой на этот
файл (файл перезаложить/заменить — для этого есть кнопка «📧 Сообщить
технологу»).

ЧТО СДЕЛАНО
-----------
src/routes/zaprosKpRoutes.js (guard «✅ T91», правки только констант):
1) CHECK_URL_FILE_TIMEOUT_MS: 15000 -> 30000 — ожидание ответа файлового
   сервера/API Яндекса на каждый запрос. Текст ошибки формируется из этой
   константы динамически, поэтому теперь: «Таймаут 30 с — сервер не ответил».
2) CHECK_URL_FIRST_BYTE_MS: 12000 -> 20000 — ожидание первого байта после
   заголовков («Таймаут — сервер не начал передачу файла») — та же фаза
   «подзависания» Яндекса, увеличено пропорционально.
НЕ менялось (осознанно):
- CHECK_URL_TOTAL_BUDGET_MS = 120000 — общий бюджет проверки остался 120 с,
  чтобы долгая проверка не упиралась в лимиты браузера/прокси; файлы, не
  уложившиеся в бюджет, честно помечаются «не проверено — превышен лимит
  времени» и видны в отчёте отдельной группой «⏳ Не проверены».

ФАЙЛЫ
-----
src/routes/zaprosKpRoutes.js   — таймауты проверки ссылки (константы T91)

УСТАНОВКА
---------
1. Сделать резервную копию проекта.
2. Заменить файл src/routes/zaprosKpRoutes.js файлом из архива.
3. Перезапустить сервер приложения (daemon на :3000 / песочница на :3110).
   Клиентские файлы не менялись — перезагрузка страницы (Ctrl+F5) не требуется,
   но после замены серверного файла сервер перезапустить ОБЯЗАТЕЛЬНО.
Требуется: T89+ (кнопка проверки ссылки) и T90+ (скрываемый отчёт, письмо
технологу) — данный архив правит только серверные константы той проверки.

КАК ПОЛЬЗОВАТЬСЯ
----------------
Без изменений: страница «Запросы на коммерческие предложения» -> поле
«Ссылка» -> кнопка «🔗 Проверить загрузку». Проверка проходит по публичной
ссылке, пробно скачивает каждый файл (сами файлы не сохраняются) и показывает
отчёт: что грузится, а что нет. Теперь каждый файл ждёт ответа до 30 с.
Если файл стабильно даёт «HTTP 500 — file IO failure…» — это битый файл на
Яндекс.Диске: нажмите «📧 Сообщить технологу» — письмо с перечнем непрогрузив-
шихся файлов и просьбой перезаложить их или предоставить новую ссылку.
