УСТАНОВКА ОБНОВЛЕНИЯ t69 — «График изготовления»: сохранение переведено на штатный механизм пакетного обновления (batch-update.js)
======================================================================================================

ЧТО СДЕЛАНО
-----------
Страница «График изготовления» теперь использует ШТАТНЫЙ механизм блокировки
обработки WebSocket-уведомлений во время операций с таблицами (batch-update.js,
«МЕНЕДЖЕР ПАКЕТНЫХ ОБНОВЛЕНИЙ») — тот же, что и на всех остальных страницах
проекта (Заказы, Коммерческие предложения, Транспортные операции и др.).

Раньше (обновление t68) для защиты процесса сохранения использовался отдельный
служебный флаг внутри кода страницы. Теперь он заменён стандартным механизмом:
это единообразно с остальным проектом и исключает расхождение поведения при
будущих доработках.

КАК ЭТО РАБОТАЕТ
----------------
1. При нажатии «Сохранить» менеджер пакетных обновлений помечает таблицы
   «grafik» и «plan» как обрабатываемые (batch).
2. Пока идёт сохранение, серверные WebSocket-уведомления об изменении этих
   таблиц централизованно игнорируются (в консоли видно «[WS] Игнорируем
   data_changed(...) — идёт batch update») — страница не перезагружает данные
   посреди цикла сохранения. Именно это защищает от потери правок строк 3+
   (баг, исправленный в t68).
3. По окончании сохранения блокировка снимается автоматически (даже при
   ошибке), и страница снова реагирует на изменения других пользователей.
4. Повторное нажатие «Сохранить» во время сохранения игнорируется
   (проверка через штатный isProcessing).

Поведение пользователя НЕ изменилось: все изменённые строки сохраняются
целиком, тост «Сохранено позиций: N», ошибки отдельных строк не останавливают
остальные.

СОСТАВ АРХИВА
-------------
  public/js/modules/grafik.js   — логика страницы графика (saveAll через batchManager)
  public/js/app-grafik.js       — точка входа (WebSocket-обработчик страницы)
  README-УСТАНОВКА.txt          — этот файл

ТРЕБОВАНИЯ
----------
Механизм batch-update.js (public/js/common/batch-update.js) есть в проекте
изначально и уже используется другими страницами — отдельно устанавливать
ничего не нужно. Обновление t68 должно быть установлено (файлы t69 включают
его исправления).

КАК УСТАНОВИТЬ
--------------
1. Остановить сервер (окно с node server.js — Ctrl+C).
2. Скопировать 2 файла из архива в папку проекта С ЗАМЕНОЙ:
     public/js/modules/grafik.js
     public/js/app-grafik.js
3. Запустить сервер заново (node server.js, порт 3110).
4. Открыть страницу «График изготовления» и нажать Ctrl+F5 (обновление со
   сбросом кэша).

ПРОВЕРКА ПОСЛЕ УСТАНОВКИ
------------------------
1. Измените месячные количества в НЕСКОЛЬКИХ строках (5-10 позиций).
2. Нажмите «Сохранить» — тост «Сохранено позиций: N», все значения в базе
   (кнопка F12 -> Console покажет строки «[BatchUpdate] begin(grafik)» /
   «end(grafik)» — признак работы штатного механизма).
3. Откройте страницу графика на двух компьютерах: изменение, сделанное на
   одном, появляется на другом (вне сохранения уведомления работают как
   раньше).

Если что-то не так — верните резервные копии двух файлов.
