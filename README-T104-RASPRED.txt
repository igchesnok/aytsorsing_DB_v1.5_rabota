T104 — «ОПЛАТА РАБОТ»: РЕЖИМЫ, ОБЯЗАТЕЛЬНЫЕ ФИЛЬТРЫ, АВТОФИЛЬТРЫ,
РАСПРЕДЕЛЕНИЕ СУММЫ ПЛАТЕЖКИ ПО ГРУЗОВЫМ ПОЗИЦИЯМ
База: ваш снапшот v1.5_rabota_102 со всеми правками вплоть до T103.

ЧТО СДЕЛАНО

1. ПОЧИНЕНА КНОПКА «➕» И РЕЖИМЫ (создание / редактирование)
   • Заголовок таблицы «Оплаты по выбранной операции» или кнопка «➕» —
     РЕЖИМ СОЗДАНИЯ: форма полностью очищается, выделение снимается,
     заголовок формы «Оплата работ — СОЗДАНИЕ новой оплаты» (зелёный).
   • Клик по платежному документу в таблице оплат — РЕЖИМ РЕДАКТИРОВАНИЯ:
     заголовок «Оплата работ — РЕДАКТИРОВАНИЕ № …» (синий).
   • «💾» сохраняет по текущему режиму: создание — новая оплата,
     редактирование — обновление полей. Больше одна кнопка не делает
     «и то, и другое» незаметно для оператора.

2. ОБЯЗАТЕЛЬНЫЕ ФИЛЬТРЫ «Фирма» и «№ зак. дог.»
   • Платежка жестко привязана к фирме и № заказа к договору — поэтому оба
     фильтра обязательны (в панели помечены «*»): пока не выбраны, кнопка
     «➕» заблокирована с подсказкой-тултипом; при сохранении/привязке —
     дополнительная проверка.
   • «№ зак. дог.» теперь ВЫПАДАЮЩИЙ СПИСОК: варианты собираются из заказов
     позиций операций (было ручным вводом).
   • Выбранные фирма и заказ ДУБЛИРУЮТСЯ В ФОРМЕ для информации
     (блок «Фирма документа», «№ заказа (дог.)»).

3. АВТОФИЛЬТРЫ ПО ТИПУ ОПЛАТЫ
   • «Предоплата (аванс)» → автоматически фильтр «№ эт.» = 1 (новый
     select-фильтр в панели), тип перевозки сбрасывается.
   • «Окончательный расчёт» → автоматически «Тип перевозки» =
     «Получение готовой продукции», «№ эт.» сбрасывается.
   • Дальше оператор сам выбирает нужную транспортную операцию.
   • Сервер поддержал параметр nomshag (этап шага маршрута партий операции).

4. РАСПРЕДЕЛЕНИЕ СУММЫ ПЛАТЕЖКИ ПО ПОЗИЦИЯМ (главное)
   Раньше вся сумма оплаты засчитывалась КАЖДОЙ привязанной позиции —
   результат был некорректным. Теперь:
   • Связь «оплата ↔ позиция» стала М:М с суммой: новая таблица
     oplata_poz (id, id_oplata_rabot, id_gryz_poz, summa). Одна позиция
     может входить в НЕСКОЛЬКО платежек (аванс + окончательный расчёт),
     и по каждой платежке на позицию относится только ЧАСТЬ суммы.
   • При создании оплаты («💾») отмеченные позиции открывают модалку
     «Распределение суммы платежки по грузовым позициям»: по каждой
     позиции вводится своя часть суммы. Живой контроль: «Распределено по
     документу: X ₽ из Y ₽»; при превышении суммы документа (итого с НДС)
     — красное предупреждение и блокировка «OK».
   • Кнопка «🔗 Привязать» открывает ту же модалку для выбранной платежки:
     существующие суммы подставляются и могут быть изменены (UPSERT).
     Позиции, привязанные ранее с другими суммами, не затрагиваются.
   • «🔓 Снять привязку» снимает привязку только ТЕКУЩЕЙ платежки —
     связи других платежек позиции сохраняются.
   • Серверная валидация: сумма всех распределений платежки ≤ сумма
     документа (итого с НДС по договору; если ставка НДС не найдена —
     сумма без НДС). Изменение суммы документа ниже уже распределённой —
     отклоняется с понятным сообщением.
   • Лимит/суммы видны в форме (строка «Распределено по позициям»),
     в таблице оплат (колонка «Распред. ₽»), в таблице позиций:
       «К опл. ₽» — часть ТЕКУЩЕЙ платежки, отнесённая позиции;
       «Оплачено ₽» — сумма частей ВСЕХ платежек позиции;
       «Оплата (акт/УПД)» — список актов всех платежек позиции.
   • Отчёт «Плоская таблица» переведён на oplata_poz (позиция — части
     платежек; для старых данных перенесено: вся сумма платежки).
   • Совместимость: gryz_poz.id_oplata_rabot сохраняется (первая оплата
     позиции); старые привязки автоматически переносятся в oplata_poz
     при старте сервера (миграция в консоли).
