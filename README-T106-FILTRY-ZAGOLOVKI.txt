T106 (ПРОДОЛЖЕНИЕ) — «ОПЛАТА РАБОТ»: ФИЛЬТРЫ ПЕРЕЗагРУЖАЮТ ВСЕ ТАБЛИЦЫ,
КЛИК ПО ЗАГОЛОВКУ ТАБЛИЦЫ — ПОЛНЫЙ СБРОС ВКЛЮЧАЯ ФИЛЬТРЫ
==========================================================================
База: ваш снапшот aytsorsing_DB_v1.5_rabota_106 — все правки T102–T106
(«Не распределено», панель шагов) СОХРАНЕНЫ, поверх добавлено новое.

ЧТО СДЕЛАНО
-----------
1. ИЗМЕНЕНИЕ ЛЮБОГО ФИЛЬТРА ПЕРЕЗагРУЖАЕТ ВСЕ ТАБЛИЦЫ СТРАНИЦЫ
   Выбор или изменение в ЛЮБОМ из шести полей фильтров («Фирма»,
   «Дата отправки», «№ эт.», «Тип перевозки», «№ зак. дог.»,
   «№ зак. ПТО») и кнопка «🔄» вызывают единый метод applyFilters():
   • транспортные операции перечитываются с сервера по текущим фильтрам;
   • если операция осталась выбранной — ЕЁ оплаты и грузовые позиции
     тоже перечитываются с сервера (устаревших данных в таблицах
     «Оплаты по выбранной операции» и «Грузовые позиции операции»
     не остаётся); при выбранной платежке заново читается её
     распределение (колонка «К опл. ₽», строка «Не распределено»);
   • если операция скрылась фильтром — её выбор снимается, таблицы
     оплат и позиций очищаются, НО ФИЛЬТРЫ ОСТАЮТСЯ такими, как их
     выставил оператор (внутренний сброс resetOperState фильтры
     не трогает).

2. КЛИК ПО ЗАГОЛОВКУ ЛЮБОЙ ТАБЛИЦЫ — ПОЛНЫЙ СБРОС СОСТОЯНИЙ,
   В ТОМ ЧИСЛЕ ФИЛЬТРОВ
   Одинаково для заголовков всех трёх таблиц («Транспортные операции»,
   «Оплаты по выбранной операции», «Грузовые позиции операции»):
   • снимаются выделение операции, выделение платежки и отметки
     (галочки) грузовых позиций;
   • форма возвращается в режим СОЗДАНИЯ новой оплаты (поля очищены);
   • ВСЕ ШЕСТЬ фильтров очищаются;
   • таблица операций перезагружается БЕЗ фильтров (полный список),
     таблицы оплат и позиций пусты.
   Панель шагов платежки возвращается в заблокированное состояние.
   Кнопка «✖ Сброс» в панели фильтров — то же самое, но это её прежняя
   роль (очистить фильтры + перезагрузить все таблицы).

3. ЧТО НЕ ИЗМЕНИЛОСЬ (регрессия проверена)
   • Кнопка «➕» — режим создания оплаты С СОХРАНЕНИЕМ выбранной
     операции и фильтров (как в T104): кликать заголовок таблицы оплат
     для этого больше не обязательно.
   • Автофильтры по типу оплаты (аванс → № эт. = 1; окончательный
     расчёт → «Получение готовой продукции») применяются только пока
     операция не выбрана (T105) — и теперь перезагружают все таблицы.
   • «Не распределено (без НДС)», модалка распределения, шаги 1–4
     платежки (T106) работают как раньше — поверх этих данных
     исправлений нет.

УСТАНОВКА
---------
1. Остановить сервер (порт 3110).
2. Скопировать 2 файла поверх одноимённых в корне проекта
   (пути — от корня aytsorsing_DB_v1.5_rabota).
3. EOL в zip сохранены как в репозитории (CRLF) — копировать поверх,
   не пересохраняя редактором.
4. Запустить сервер, открыть «Оплата работ», выполнить Ctrl+F5.
Миграции БД не требуются — структура данных не менялась.

ПРОВЕРЕНО (браузерные тесты Playwright, 59/59)
----------------------------------------------
Часть 1 — фильтры перезагружают все таблицы:
  • смена «Фирма» / «№ зак. дог.» → перезагрузка операций;
  • при выбранной операции смена «Дата отправки» и «№ эт.» →
    перечитаны И операции, И оплаты, И позиции (контроль по сетевым
    запросам /api/oplata/operatsii, /zapisi, /pozicii);
  • операция осталась выбранной, если фильтр её не скрывает;
  • фильтр, скрывающий операцию → выбор снят, оплаты/позиции очищены,
    фильтры остались.
Часть 2 — клик по заголовку каждой из 3 таблиц:
  • все 6 фильтров очищены; операции перезагружены без фильтров;
    оплаты/позиции очищены; выделения и отметки сняты; форма в режиме
    СОЗДАНИЯ.
Часть 3 — регрессия:
  • «➕» не сбрасывает фильтры и операцию, форма — СОЗДАНИЕ;
  • создание платежки с распределением (модалка, OK) → платежка
    выделена, шаг 1 АКТИВЕН, у аванса шаги 3/4 скрыты;
  • «Не распределено (без НДС)» заполнено;
  • клик по заголовку оплат после создания — полный сброс;
  • консоль браузера без ошибок. Тестовая платежка удалена,
    БД восстановлена байт-в-байт.
