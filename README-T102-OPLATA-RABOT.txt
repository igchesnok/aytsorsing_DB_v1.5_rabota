T102 — ОПЛАТА РАБОТ (страница «Оплата работ» + инверсия связи с грузовыми позициями)
=====================================================================================

ЧТО СДЕЛАНО
-----------
1. ИНВЕРСИЯ СВЯЗИ «оплата работ ↔ грузовые позиции» (миграция БД):
   БЫЛО: oplata_rabot.id_gryz_poz — 1 оплата на 1 позицию (неверно);
   СТАЛО: gryz_poz.id_oplata_rabot — 1 оплата (акт/УПД) covers НЕСКОЛЬКО позиций.
   - В oplata_rabot поле id_gryz_poz УДАЛЕНО (вместе с индексом idx_oplata_gryz).
     SQLite не позволяет DROP COLUMN, на которую ссылается FK внутри таблицы,
     поэтому таблица пересоздаётся штатной процедурой (копия → перенос → замена).
   - В gryz_poz добавлена колонка id_oplata_rabot (+ индекс idx_gryz_oplata).
   - Миграция автоматическая при старте сервера; существующие ссылки
     переносятся (позиции достаётся первая по created_at оплата).

2. НОВАЯ СТРАНИЦА «💳 Оплата работ» (public/pages/payment.html — пункт меню
   «11. 💳 Оплата работ» главного окна):
   - Фильтры транспортных операций: Фирма / Дата отправки / Тип перевозки + «Сброс».
   - Таблица «Транспортные операции» (дата отправки, фирма, тип перевозки,
     направление, № рейса, груз, позиций, оплат, статус).
   - Форма «Оплата работ»: тип оплаты (Предоплата (аванс) / Окончательный
     расчёт), дата предоставления документов, № акта/УПД, № счёт-фактуры,
     сумма к оплате ₽ БЕЗ НДС, НДС % (авто из договора), Сумма НДС и
     Итого с НДС (рассчитываются на лету), примечание.
   - Таблица «Оплаты по выбранной операции» (➕ новая / 💾 сохранить / ✖ удалить).
   - Таблица «Грузовые позиции операции»: № чертежа, наименование оснастки,
     количество в позиции, привязанная оплата, договор.
     Отметка позиций — Ctrl+click (как на «Плане перевозок»).
   - Кнопки «🔗 Привязать» / «🔓 Снять привязку» — oplata_rabot вешается на
     грузовые позиции документа выбранной транспортной операции
     (gryz_poz.id_oplata_rabot).

3. НДС ИЗ ДОГОВОРА: ставка берётся из dogovor.hdc; договор определяется по
   dog_osnov грузовых позиций (plan_perevozok → dogovor.nom_dogovor).
   Сумма НДС = Сумма × НДС% / 100; Итого = Сумма + НДС. Значения вычисляются
   при чтении (в БД не хранятся — не устаревают при изменении ставки).

4. ОТЧЁТ «Плоская таблица» переведён на новую связь
   (gryz_poz.id_oplata_rabot → oplata_rabot) — колонки УПД/акта работают как прежде.

API (/api/oplata)
-----------------
  GET    /operatsii?firma=&data=&tip=   — операции с фильтрами
  GET    /pozicii?operId=               — грузовые позиции (чертёж/наименование/кол-во/договор)
  GET    /zapisi?operId=                — оплаты операции (НДС и суммы расчётные)
  POST   /zapisi                        — создать оплату + привязать позиции {id_oper, pozIds, ...}
  PUT    /zapisi/:id                    — обновить поля оплаты
  DELETE /zapisi/:id                    — удалить оплату (сняв привязки)
  POST   /privyazat                     — привязать позиции {id_oper, oplId, pozIds}
  POST   /otvyazat                      — снять привязку {id_oper, pozIds}

УСТАНОВКА
---------
1. Скопировать файлы поверх проекта (структура совпадает).
2. Перезапустить сервер — миграция выполнится автоматически
   (в логе: «✅ oplata_rabot пересоздана без id_gryz_poz (T102…)»).
3. Требуется SQLite >= 3.35 (как и для миграций T51).

ПРИМЕЧАНИЯ
----------
- Оплата обязана быть привязана хотя бы к одной позиции (создание проверяет).
- Позиция несёт только одну оплату; повторная привязка занятой позиции
  отклоняется с сообщением (сначала «🔓 Снять привязку»).
- Оплата, отвязанная от всех позиций, исчезает из списка операции (список
  строится через позиции) — форма остаётся заполненной: можно привязать
  заново или удалить оплату «✖».
- tip_oplaty: 'avans' / 'okonchatelny_raschet' — как использует отчёт
  «Плоская таблица» (аванс у строки отправки, окончательный расчёт у прихода).
