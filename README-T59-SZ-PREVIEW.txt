✅ T59: ПРЕДПРОСМОТР ФАЙЛА СЗ «Заявка на отгрузку» В БРАУЗЕРЕ ПЕРЕД ОТПРАВКОЙ НА ПОРТАЛ
========================================================================================

ЧТО СДЕЛАНО
-----------
При нажатии кнопки «Создать СЗ в системе» (вкладка «Документы» редактора
транспортных операций) файл СЗ теперь СНАЧАЛА показывается в браузере —
модальное окно предпросмотра с запросом дальнейших действий. Референс —
страница «Заказы по договорам», кнопка «Отправить заказы контрагентам»
(тот же общий компонент предпросмотра public/js/common/excel-preview.js).

ПОРЯДОК РАБОТЫ
--------------
1) «Создать СЗ в системе» — сервер выполняет шаги 3-6 VBA
   CommandButton12_Click: создаёт документ в ЭДО АВТОВАЗа (tportal.vaz.ru),
   заполняет карточку (подписант, D_NOM/DATE_DOC), формирует файл
   «Заявка на отгрузку (...)» из шаблона. НА ПОРТАЛ ФАЙЛ НЕ ГРУЗИТСЯ,
   В БД sz_transport_* НЕ ПИШУТСЯ.
2) Открывается модальное окно «Предпросмотр СЗ перед загрузкой на портал»:
   в iframe — лист «Заявка NEW!» файла (то же, что видно в Excel),
   кнопки: «⬇ Скачать XLSX», «✖ Отменить создание СЗ»,
   «✅ Подтвердить и загрузить на портал».
3) «Подтвердить…» — выполняются шаги 7-8 VBA: загрузка файла на портал
   (filesave.aspx) и запись sz_transport_id/nomer/data в транспортную
   операцию (UpdateIDTrOp). Поля вкладки и уведомления — как раньше.
4) «Отменить…» — локальный файл заявки удаляется, БД не меняется — СЗ
   можно создать заново. ВНИМАНИЕ: документ в ЭДО АВТОВАЗа к моменту
   предпросмотра УЖЕ создан (номер/дата СЗ берутся из его карточки) —
   при отмене он остаётся на портале черновиком (то же происходит и
   раньше при любой неудаче после создания документа; удаления через
   API портал не предоставляет). Лишний черновик безвреден: он не
   подписан и никуда не отправлен.
5) Если конвертер предпросмотра не сработал (preview_html пуст) —
   классический вопрос «Загрузить файл заявки на портал?» — старое
   поведение сохраняется.

ЧЕСТНЫЙ ПРЕДПРОСМОТР (почему это не «картинка»)
-----------------------------------------------
Файл СЗ получается из шаблона: данные пишутся в ячейки, но формульные
ячейки листа несут КЭШ шаблонных примеров (AB6 «ПТО; Чесноков…»,
объём AM6 0,8, тип кузова CJ6 «Тент» и т.д.). Excel пересчитывает их при
открытии (в шаблоне включён fullCalcOnLoad), а конвертер HTML (ExcelJS)
формулы НЕ вычисляет. Поэтому перед конвертацией в HTML по файлу
проходится препроцессор (szExcel.buildPreviewBuffer):
  - устаревший кэш <v> снимается у ВСЕХ формульных ячеек строк 6..32
    листа «Заявка NEW!» — в предпросмотре нет примеров из шаблона;
  - объём AM (Д×Ш×В×места) пересчитывается по написанным AI..AL —
    ROUNDUP до 1 знака, как формула шаблона (пример: 6×1,5×0,167×1 -> 1,6;
    1,15×0,14×0,004×1 -> 0,1);
  - адресные блоки AB..AF (единственные формулы строк 6..32, ссылающиеся
    только на свою строку) вычисляются мини-интерпретатором
    (IF/=/&/CHAR/ссылки) — в предпросмотре видны адреса и контактные лица;
    slave-формулы shared-групп берут текст мастера со сдвигом строк;
  - VLOOKUP-колонки CE..CJ (перевозчик/режим и т.п.) ссылаются на другие
    листы — в предпросмотре они пустые, в Excel после открытия
    пересчитываются. Это НЕ влияет на сам файл: он отдаётся на портал
    в исходном виде, препроцессор работает только с копией для HTML.
  - скрытые строки/колонки шаблона в предпросмотре тоже скрыты —
    картинка соответствует тому, что видно в Excel.

НОВЫЕ ЗАВИСИМОСТИ
-----------------
НЕТ. exceljs/jszip уже используются (просмотр Excel на странице «Заказы
по договорам» работает на тех же библиотеках).

ЗАПУСК
------
Как обычно: _run-server-sqlite3_DB.bat (Node.js, порт 3110, вход admin/1234).
Первое открытие предпросмотра занимает несколько секунд (конвертация
большого листа) — файл кэшируется сервером в памяти на время запроса.

ПРОВЕРЕНО
---------
- скрипт scripts-поставки: szRows -> generateShipmentFile ->
  buildPreviewBuffer -> generatePreviewHTML на реальном шаблоне с двумя
  типами тарных мест (техспецсварка): объёмы 1,6 и 0,1, «+» в колонке
  «Требуется заказ транспорта?», названия тарных мест, адресные блоки,
  отсутствие устаревших примеров шаблона;
- xlsx-буфер предпросмотра валиден (zip + well-formed XML, ExcelJS,
  LibreOffice открывает без восстановления);
- регрессия T58 (строки тарных мест, «+», названия мест) — без изменений,
  итоговый файл на портал не изменился;
- браузером (Chromium): модальное окно, вкладка, «Скачать XLSX»,
  «Подтвердить…» (promise true, окно закрылось), «Отмена»/Escape,
  обратная совместимость дефолтных подписей; страница «Заказы по
  договорам» работает;
- гварды API: операция не выбрана/не найдена, «Письмо уже было создано»,
  некорректное имя файла (path traversal отсечён), файл не найден.
- Полный цикл с порталом ЭДО (tportal.vaz.ru) проверяется на рабочем
  контуре: в песочнице портал недоступен — код шагов 3-8 не менялся,
  изменён только порядок их вызова.
