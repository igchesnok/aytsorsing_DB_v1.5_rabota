T105 — «ОПЛАТА РАБОТ»: МОДАЛКА РАСПРЕДЕЛЕНИЯ — СРАВНЕНИЕ БЕЗ НДС
И ПРЕДЗАПОЛНЕНИЕ СУММ ПО ТИПУ ПЛАТЕЖА
База: ваш снапшот v1.5_rabota со всеми правками вплоть до T104.

ЧТО СДЕЛАНО

1. СРАВНЕНИЕ «РАСПРЕДЕЛЕНО X ИЗ Y» — БЕЗ НДС
   • Лимитом распределения теперь является СУММА ПЛАТЕЖКИ БЕЗ НДС (поле
     «Сумма к оплате»). Всё, что связано с НДС, — РАСЧЁТНЫЕ величины:
     в модалке рядом с контролем показываются «НДС 22%: … ₽ · Итого
     с НДС: … ₽ (расчётно)» по ставке из договора позиций.
   • Строка «Распределено по позициям» в форме — тоже «X из Y ₽
     (без НДС)».
   • Серверная валидация переведена на тот же лимит: сумма всех
     распределений платежки ≤ сумма документа БЕЗ НДС (создание оплаты,
     «🔗 Привязать», изменение суммы документа — POST/PUT /api/oplata/
     zapisi, POST /api/oplata/privyazat). Тексты ошибок говорят
     «… ₽ без НДС».
   • В ответе /api/oplata/zapisi лимит отдаётся полем limit_rasp
     (сумма документа без НДС).

2. ПРЕДЗАПОЛНЕНИЕ СУММ ПО ПОЗИЦИЯМ (модалка распределения)
   • Тип платежа «Предоплата (аванс)»: сумма позиции = Стоимость ₽ ×
     процент аванса из договора (таблица dogovor, поле predoplata_pr).
     Пример: Стоимость 360 000 ₽ × 30% = 108 000 ₽. Если процент аванса
     в договоре не заполнен — поле остается пустым, а инфо-строка
     модалки предупреждает «…суммы задайте вручную».
   • Тип платежа «Окончательный расчёт»: сумма позиции = Стоимость ₽ −
     оплачено по позиции другими платежками (фактически уплаченный
     аванс — он равен колонке «Оплачено ₽» таблицы «Грузовые позиции
     операции»). Итог после оплаты: «Оплачено ₽» позиции = стоимости
     позиции.
   • При открытии модалки предзаполняются только ПУСТЫЕ поля —
     уже введенные/существующие суммы не затрагиваются.
   • Новая кнопка «⟳ Автозаполнение» в модалке: пересчитывает суммы
     заново по текущему типу платежа (перезаполняет ВСЕ поля).

3. СМЕНА ТИПА ОПЛАТЫ НЕ «ТЕРЯЕТ» ВЫБРАННУЮ ОПЕРАЦИЮ
   • Автофильтры по типу оплаты (аванс → № эт. = 1; окончательный →
     «Получение готовой продукции») применяются только пока транспортная
     операция еще не выбрана. Если операция уже выбрана — смена типа
     оплаты оставляет фильтры и выбор операции без изменений (раньше
     автофильтр мог скрыть выбранную операцию и сбросить форму).

ФАЙЛЫ (распаковать в корень проекта с заменой):
  src/routes/oplataRabotRoutes.js  — лимит без НДС (POST/PUT/privyazat),
                                     predoplata_pr в /api/oplata/pozicii,
                                     limit_rasp в /api/oplata/zapisi
  public/js/modules/oplataRabot.js — контроль «Распределено X из Y»
                                     (без НДС) + расчётный НДС/итого,
                                     предзаполнение и «⟳ Автозаполнение»,
                                     защита выбранной операции
  public/pages/payment.html        — инфо-строка предзаполнения, кнопка
                                     «⟳ Автозаполнение», тултипы
