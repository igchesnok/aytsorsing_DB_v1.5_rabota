ЗАПРОСЫ КП: СКРЫВАЕМЫЙ ОТЧЁТ ПРОВЕРКИ ССЫЛКИ + ПИСЬМО ТЕХНОЛОГУ (T90)
======================================================================

ТРЕБОВАНИЯ
----------
Требуется поставка T89 «проверка доступности файлов по ссылке»
(в файлах этой поставки все предыдущие изменения уже включены —
файлы заменяются целиком).

ЧТО СДЕЛАНО
-----------

1. ОТЧЁТ ПРОВЕРКИ ССЫЛКИ — СКРЫВАЕМЫЙ (КНОПКА-ТРЕУГОЛЬНИК)
   На странице «Запросы на коммерческие предложения», шаг 2
   «Ссылка от технолога»: справа в строке кнопки «🔗 Проверить
   загрузку» добавлена кнопка-треугольник — та же, что сворачивает
   блоки фильтров (class filter-toggle-btn). После проверки отчёт
   развёрнут (▲); клик сворачивает его (▼), повторный клик —
   разворачивает. До первой проверки треугольника нет.
   Отчёт автоматически сбрасывается: при изменении ссылки,
   при выборе другого запроса, в режиме «новая запись».

2. КНОПКА «📧 СООБЩИТЬ ТЕХНОЛОГУ» ВНУТРИ ОТЧЁТА
   Появляется в отчёте, когда по ссылке есть что сообщить:
   - в красном блоке «❌ Не прогрузились (N)» — под перечнем
     непрогрузившихся файлов;
   - либо в мини-отчёте, когда файлы по ссылке получить не
     удалось целиком (ссылка удалена/недоступна).
   Если все файлы загружаются — кнопки нет (писать не о чем).

3. ПИСЬМО ТЕХНОЛОГУ «ПО ССЫЛКЕ НЕ УДАЕТСЯ СКАЧАТЬ ФАЙЛЫ»
   Реализация — аналог кнопки шага 1 «Согласование запроса
   технологом» (тот же адресат, тот же особый режим «БЕЗ ОТПРАВКИ
   ПИСЕМ», подпись — общий шаблон):
   - адресат — технолог из поля «Технолог» (select, шаг 1),
     email берётся из справочника «Технологи»;
   - обращение по ИМЕНИ-ОТЧЕСТВУ: «Уважаемый Владимир Юрьевич!»
     (из ФИО справочника; если слов меньше трёх — ФИО целиком);
   - в тексте: № запроса и дата, ссылка, перечень файлов, которые
     не прогрузились (имена из отчёта проверки), просьба
     «перезаложить данные файлы или предоставить новую ссылку
     на черт. и 3D мод.»;
   - копия: igor.chesnokov@vaz.ru;Aleksandr.Tyurin@vaz.ru;
   - подпись — Чесноков Игорь Иванович (общий шаблон SIGNATURE,
     правится в одном месте для всех писем);
   - вложения НЕТ; даты и статусы запроса письмо НЕ меняет —
     шаги согласования не двигаются (сервисное письмо);
   - чекбокс «Без отправки писем (особый случай)» действует:
     письмо не отправляется, на экран выводится предупреждение.

НОВЫЙ СЕРВЕРНЫЙ ЭНДПОИНТ
------------------------
POST /api/email/send-url-problem { zaprosId, url, failedFiles, dryRun }
 - failedFiles — массив имён файлов (строки или объекты {name});
 - dryRun=true — без фактической отправки (для проверок/тестов);
 - ответ содержит preview { to, subject, body } — текст письма
   для самопроверки; клиент поле не использует.

УСТАНОВКА
---------
1. Остановить сервер.
2. Заменить указанные 4 файла.
3. Запустить сервер. Изменения настроек/БД не требуются.

КАК ПОЛЬЗОВАТЬСЯ
----------------
1. Откройте запрос (шаги 1–2 пройдены или заполните ссылку в шаге 2).
2. Нажмите «🔗 Проверить загрузку» — отчёт покажет, какие файлы
   по ссылке не скачиваются.
3. Если есть непрогрузившиеся — в красном блоке нажмите
   «📧 Сообщить технологу»: письмо с перечнем файлов, просьбой
   перезаложить или дать новую ссылку уйдёт технологу запроса
   (копия — Чеснокову и Тюрину).
4. Отчёт можно свернуть треугольником справа от кнопки проверки.
