ИСПРАВЛЕНО
----------
1) БАГ 1. Кнопка «Автозаполнение параметров перевозки» в РЕЖИМЕ
   ДОБАВЛЕНИЯ писала «Нет данных для автозаполнения (у позиций не
   определён ШПЗ)», хотя у каждой позиции заполнена вкладка деталей.
   Причина: pending-позиции режима создания не передавали заказ ПТО
   (zak_pto) и единичные веса — сервер вычислял ШПЗ только по zak_pto.
   Исправление:
   - transportOpsCargo.js: pending-позиция несёт zak_pto, ves_det,
     ves_zag (как у позиций режима редактирования);
   - transportOperRoutes.js: сервер принимает ШПЗ и из поля shpz
     ('с'/'о') pending-позиций, и по zak_pto; масса считается по
     единичному весу, при его отсутствии — по уже посчитанному
     суммарному (ves_det_tot/ves_zag_tot).
   В режиме редактирования ничего не изменилось (проверено тестами).

2) БАГ 2. «Связки прутков» в «Группировке тарных мест»: ширина и
   высота места НЕ пересчитывались от количества прутков (были равны
   Ø одиночного прутка). Теперь сечение связки считается так же, как
   в авто-расчёте: сторона квадрата = ceil(sqrt(N)) × Ø прутка,
   но не более 300 мм, где N — количество прутков позиции (ручное
   «Кол-во загот.» > авто-расчёт > оценка по длине прутка и детали).
   Пересчитывается при изменении состава позиций места (клиент) и
   при дозаполнении сохранённых мест с пустыми габаритами (сервер).
   Файлы: transportOpsTarn.js, tarnCalc.js

3) БАГ 3. Вес тарного места в режиме добавления не равнялся сумме
   веса заготовок позиций (уходил в оценку по габаритам — например
   2714 кг вместо 1035). После исправления (1) pending-позиции несут
   вес заготовки (ves_zag), и вес места = Σ (вес заготовки × кол-во)
   по позициям места — как в режиме редактирования и как считал
   прежний алгоритм.

4) БАГ 4. Наименование груза «Детали на поддонах: …» заменено на
   «Детали на деревянной таре: …» (как в VBA-оригинале
   CalculatePalletCountByOrder). Старое имя из сохранённых операций
   тоже заменяется при следующем автозаполнении. Префиксы
   «Заготовки в листах/прутках», «Смешанный груз» не тронуты.
   Файлы: transportOperRoutes.js, transportOpsParams.js

База данных firmy.db, config/edo.json и документы архив НЕ трогает.

УСТАНОВКА
---------
  1) Остановить сервер (Ctrl+C в окне node).
  2) Распаковать архив в КОРЕНЬ проекта с заменой файлов
     (структура папок архива совпадает со структурой проекта).
  3) Запустить: node server.js
  4) В браузере: Ctrl+F5.

ПРОВЕРЕНО
---------
  - node --check всех файлов — без ошибок;
  - авто-заполнение в режиме создания: ШПЗ определяется (оба
    источника), масса = Σ(вес заготовки × кол-во); без ШПЗ —
    прежняя деградация no_data;
  - авто-заполнение в режиме редактирования — без изменений;
  - связки прутков: 40 деталей (4 прутка) -> сечение 0.04 м;
    400 (37 прутков) -> 0.14 м; много прутков -> 0.3 м (лимит);
  - вес места = Σ ves_zag × кол-во (клиент и сервер);
  - групповой раскрой листов, деревянная тара, М-15, СЗ —
    без изменений (движок сверен с прежней версией байт-в-байт
    по результатам: 43 листа / экономия 3 / вес 6636.8);
  - UI (модалка «Расчёт тарных мест») — консоль браузера чиста.
