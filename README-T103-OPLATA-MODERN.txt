ОПЛАТА РАБОТ — МОДЕРНИЗАЦИЯ СТРАНИЦЫ (T103)
============================================
Базовая поставка: aytsorsing_DB_v1.5_rabota со всеми изменениями до T102
включительно (страница «Оплата работ» T102 обязательна).

ЧТО ИЗМЕНЕНО
------------
1. ТАБЛИЦА «ТРАНСПОРТНЫЕ ОПЕРАЦИИ» (страница «Оплата работ»)
   • Удалены колонки: «Тип перевозки» (transport_tip), «Направление», «№ рейса».
   • Добавлены колонки как в «Текущем плане перевозок» страницы «План перевозок»:
     - «№ эт.» — № этапа маршрута (расшифровка в тултипе);
     - «Тип перев.» — тип перевозки, шаг маршрута (расшифровка в тултипе).
   • Данные берутся по заявкам партий операции:
     gryz_poz → plan_perevozok.id_shag → shagi_marshruta → transport_types.
     Если в операции партии нескольких этапов — значения перечисляются через запятую.

2. ТАБЛИЦА «ГРУЗОВЫЕ ПОЗИЦИИ ОПЕРАЦИИ» — новые колонки
   (названия короткие, расшифровки — в тултипах заголовков):
   • «№ запр.»    — № запроса КП позиции (те же субзапросы, что в «Плане производства»);
   • «№ зак. дог.»— № заказа к договору с датой (как в «Плане производства»);
   • «Кол. зак.»  — количество по заказу (= план по позиции, plan.plan_god_kolvo);
   • «Цена КП»    — стоимость одной детали по лучшему КП (kp.cena_postavshika
                    назначенного плану КП, plan.id_kp), ₽ без НДС;
   • «Стоимость ₽»— стоимость планового количества, ₽ = Кол.зак × Цена КП;
   • «Оплачено ₽» — оплачено по позиции, ₽ (сумма всех оплат, привязанных
                    к позиции через gryz_poz.id_oplata_rabot).
   Колонка T102 «Сумма оплаты, ₽» заменена на «Оплачено ₽» — при текущей схеме
   (одна оплата на позицию) значения совпадают, но «Оплачено ₽» — точная
   семантика «суммы всех платежек позиции».

3. ФИЛЬТРЫ ОПЕРАЦИЙ — два новых текстовых фильтра:
   • «№ зак. дог.» — по номеру заказа к договору любой позиции плана, чья партия
     едет в операции (poz_zakaz_dogovora → zakaz_po_dogovoru.nomer_zakaza);
   • «№ зак. ПТО»  — по plan.zak_pto позиций плана операции.
   Оба — частичное совпадение, БЕЗ учёта регистра кириллицы и с распознаванием
   латинских двойников (Кир→Лат) — используется cyrGlobPattern из
   src/routes/helpers/queryBuilder.js (тот же механизм, что фильтр «№ запроса»
   в «Плане производства»).
   ВАЖНО: параметр tip старого фильтра «Тип перевозки» теперь сверяется с типом
   шага маршрута (transport_types.nazvanie_operatsii, например «Отправка
   заготовки»), а не с transport_oper.transport_tip («Тентованный»).

4. ОБЩИЙ КОМПОНЕНТ virtual-table.js — аддитивная поддержка тултипов заголовков:
   колонка может задать `tip: 'расшифровка'` — показывается при наведении на
   заголовок (cursor: help). На остальные страницы влияния нет.

ФАЙЛЫ ПОСТАВКИ (4)

  src/routes/oplataRabotRoutes.js     — SQL операций/позиций + фильтры (LF)
  public/js/modules/oplataRabot.js    — колонки, тултипы, фильтры (CRLF)
  public/pages/payment.html           — 2 новых фильтра в тулбаре (CRLF)
  public/js/common/virtual-table.js   — тултипы заголовков, c.tip (CRLF)

УСТАНОВКА
---------
1. Остановить сервер (порт 3110).
2. Скопировать 4 файла поверх одноимённых в корне проекта
   (пути — от корня aytsorsing_DB_v1.5_rabota).
3. Проверить EOL: oplataRabotRoutes.js — LF; остальные — CRLF (в zip сохранены).
4. Запустить сервер, открыть «Оплата работ», выполнить Ctrl+F5.
