БАГ 1. «Расчёт тарных мест»: штабелируемость не устанавливается
        в ручном режиме
----------------------------------------------------------------
Симптом: в модальном диалоге «Расчёт тарных мест» выбираешь в
форме справа «Штабелируемость» (да/нет) — значение НЕ меняется:
ни в форме, ни в колонке «Штабел.» таблицы группировки.

Причина: селект #tfGrpSht отрисовывался, но обработчик change
к нему НИКТО НЕ ПРИВЯЗЫВАЛ — выбор пользователя никуда не
записывался (в отличие от «Типа места» и «Укладки»).

Исправление (public/js/modules/transportOpsTarn.js):
  1) добавлен обработчик change селекта «Штабелируемость»:
     выбор да/нет записывается в группу (g.shtabil) и таблица
     группировки обновляется;
  2) при смене «Типа места» штабелируемость автоматически
     выставляется по правилу движка раскроя (как при
     авто-расчёте): «Пачки листов» и «Связки прутков» — «да»,
     «Деревянная тара» — «нет». Пользователь может тут же
     переопределить селектом.

Проверено в браузере: да->нет->да, колонка «Штабел.» и
сохраняемый JSON тарных мест меняются корректно.

----------------------------------------------------------------
БАГ 2. XLSX «Заявка на отгрузку» (СЗ на транспорт) — 3 дефекта
----------------------------------------------------------------
2.1. Колонки с одинаковыми данными НЕ дублировались в строки 7+.
     Было: в строке «Деревянная тара» пустовали Заказчик
     отгрузки, Грузоотправитель, Адреса, Даты, № рейса,
     Транспорт, Способ загрузки, Оформление ТН, Комментарий,
     Плательщик, Кто с ЭДО и т.д.
     Стало: в КАЖДУЮ строку тарного места (7, 8, 9…) дублируются
     все общие колонки заявки:
       - B..Z  — DataArray1 (заказчик/грузоотправитель/адреса
                 погрузки-выгрузки/контакты);
       - AH    — класс опасности груза;
       - AP..BD — дата/время отгрузки, дата/время прибытия,
                 № рейса, транспорт, способ загрузки/разгрузки,
                 температурный режим, оформление ТН, комментарий,
                 плательщик за перевозку, описание груза
                 (примечание), кто с ЭДО, причина/виновник
                 срочной перевозки.
     Своё у каждой строки остаётся: Наименование груза (AG) —
     тип места; кол-во мест (AI); длина/ширина/высота (AJ..AL);
     Объём (AM — формула шаблона); Штабелируемость (AN); Вес (AO).

2.2. Колонка «Требуется заказ транспорта?» (BE).
     Было: «+» стоял только в первой строке (умолчание шаблона),
     строки 7+ оставались пустыми.
     Стало: «+» пишется в КАЖДУЮ строку тарных мест.

2.3. Колонка «Наименование груза» — старое правило.
     Было: «Заготовки в листах: ШВЕЛЛЕР (заготовка в листах);
     ПЛАСТИНА 140X1150 (заготовка в листах); …».
     Стало: пишутся ЧЁТКИЕ названия тарных мест — по одному на
     строку: «Пачки листов», «Связки прутков», «Деревянная
     тара» (с указанием укладки, если задана, например
     «Деревянная тара (один слой)»). В строке 6 — название
     ПЕРВОГО тарного места вместо старого длинного текста;
     в строках 7+ — названия соответствующих мест (это уже
     было, дополнено дублированием общих колонок из 2.1).

Исправление (src/routes/helpers/tarnCalc.js — функция szRows,
src/routes/transportOperRoutes.js — передача a1/a2 в szRows).
Обратная совместимость: если тарные места НЕ рассчитаны,
файл формируется как прежде (одна строка 6, VBA 1:1).

Проверка: юнит-тест szRows + реальная генерация из шаблона
«Заявка на отгрузку.XLSX»; XML всех 30 частей валиден; файл
открывается LibreOffice без «восстановления»; количество
артефактов #VALUE! совпадает с базовой линией v1.5 (это
особенность формул объёма с русским десятичным разделителем —
в русском Excel, как и прежде, объём считается: 1,6 / 0,1).
