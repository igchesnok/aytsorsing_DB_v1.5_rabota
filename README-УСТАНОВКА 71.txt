T71 — «Формирование плана производства»: два исправления
==========================================================

ЧТО ИСПРАВЛЕНО
--------------

БАГ 1. Сброс фильтра фирмы при выборе строки.
  При выборе строки в таблице плана (а также при клике по шапке таблицы,
  т.е. снятии выбора) селект фильтра «Фирма» сбрасывался: значение фильтра
  затиралось данными строки. Теперь выбор в таблице НЕ влияет на поля
  фильтров: фильтры изменяются только пользователем (вводом, селектом,
  кнопками очистки).

БАГ 2. «№ запроса» заполнялся не для всех позиций.
  Ранее (t70) номер запроса брался только через ЛУЧШЕЕ КП позиции
  (plan.id_kp). Если решение по КП ещё не выбрано, колонка оставалась
  пустой, хотя запрос КП для позиции существовал. Теперь пишется запрос,
  в который позиция плана УЖЕ включена (связь kp.id_plana = plan.id),
  независимо от того, выбрано ли лучшее КП. Позиции, не включённые ни
  в один запрос, остаются с пустой колонкой — как и было задумано.
  Охват по данным: было 23 позиции с «№ запроса», стало 58.

ФАЙЛЫ В АРХИВЕ
--------------

  src/routes/helpers/syntheticTables.js      — серверный (БАГ 2)
  public/js/common/form-state-manager.js     — клиентский (БАГ 1)

УСТАНОВКА
---------

1. Скопировать оба файла поверх файлов проекта с сохранением путей.
2. ПЕРЕЗАПУСТИТЬ СЕРВЕР (обязательно: syntheticTables.js — серверный код).
3. В браузере обновить страницу плана с очисткой кэша (Ctrl+F5),
   иначе останется закэшированный form-state-manager.js.

ПРОВЕРКА
--------

- На странице «Формирование плана производства»: задать фильтр фирмы,
  выбрать строку таблицы, кликнуть по шапке — фильтры не сбрасываются.
- Колонка «№ запроса» заполнена для позиций, включённых в запросы КП,
  даже если лучшее КП ещё не выбрано.
- Остальное поведение страницы (порядок колонок t70, «№ зак. по дог.»,
  тултипы, ресайз, фильтры, импорт из буфера) не изменялось.

ТРЕБОВАНИЯ
----------

Актуальный проект v59 + t60..t70. Оба файла целиком заменяют предыдущие
версии (учитывают все правки t60..t70 этих файлов).
